# Cubence GPT‑6 Astra backend

This optional backend sends synchronized RGB, robot proprioception, declared tactile feedback and camera calibration directly to `gpt-6-astra` through Cubence. It does not use Codex authentication, an expert trajectory, privileged object poses or task-specific motion macros. The independent environment scorer decides task success after actual release, retreat and stability checks.

The native launcher owns Isaac and calls `run_episode` on an already-reset `ProjectEnvironment`. Network requests are synchronous while physics is paused; validated tools advance a bounded simulation interval and produce a new observation. This pause is inference latency, not simulated stabilization time.

## Credentials and capability check

Set `CUBENCE_API_KEY` only in the launching process environment. An interactive Bash example avoids shell history containing the value:

```bash
read -rsp 'Cubence API key: ' CUBENCE_API_KEY; echo
export CUBENCE_API_KEY
python3 scripts/probe_cubence.py \
  --output outputs/provider_probe_01 \
  --ledger outputs/cubence_budget.json \
  --capabilities text image tools structured multiturn error
```

Use the same ledger for all probes, debug runs and formal episodes. No credential, authorization header or raw provider error body is saved. The output directory must be new. Probes perform real calls and separately report text, synthetic-image recognition, function calls, JSON schema and tool-result continuation. They do not validate physical task performance. A red/blue image is generated by the probe, not loaded from private task assets.

The default configuration is `config/lab_cuvette_loading/Project_v1/policies/cubence_gpt6.json`. It explicitly pins provider `cubence`, global base URL `https://api.cubence.ai/v1`, model `gpt-6-astra` and Responses API. Returned model names are checked. Chat fallback requires an explicit configuration and recorded evidence that Responses was unsupported and Chat was supported; there is no automatic fallback to another model or service. The current closed-loop runner uses Responses.

An HTTP200 response without model identity is rejected as `RETURNED_MODEL_MISSING`; a different returned identity is `RETURNED_MODEL_MISMATCH`. Both retain the actual returned usage/cost estimate, record an error status and stop without retry or silent acceptance. A missing identity alone is not evidence that a different model ran.

`images.max_side_px`, `images.jpeg_quality` and `images.detail` explicitly configure provider image transport. Native640×480 recordings remain unchanged. Every model decision records source/transmitted resolutions and hashes, byte counts, resize scale, pixel-centre transform and the correspondingly transformed camera intrinsic matrix. A smaller provider thumbnail therefore remains a declared policy-input transform, not a change to recorded sensor resolution. The final pilot/formal configuration uses512×384 JPEG quality60 with detail=low; an actual512-pixel scene probe returned the requested model identity. Debug pilot02 used256×192 and remains separately versioned. To probe an actual camera file, add `--image /path/to/frame.png --image-max-side 512 --image-jpeg-quality 60`; retain earlier failed large-image and missing-identity probes separately.

## Actions and observations

The model receives the current `episode_id`, `observation_id`, simulation time, side/wrist RGB, joint positions and velocities, world TCP pose, total gripper opening, optional bilateral contact-force sensors and whitelisted camera calibration. Object pose, insertion depth, task phase, geometry/debug state and independent scorer internals are excluded.

The five available tools are:

- `observe`: synchronized observations; no simulation time advances.
- `move_ee`: bounded world pose (`xyz`, quaternion `wxyz`) or world/TCP delta (`xyz`, rotation vector), in metres and radians.
- `gripper`: symmetric total opening in metres and explicit force cap per finger in newtons while the arm holds its pose.
- `wait`: bounded simulation steps while holding the current command.
- `finish`: request independent scoring; cannot submit a success label.

Every motion names the current episode/observation and a unique action ID. Stale observations, invalid frames, nonfinite values, excess distance, speed, rotation, duration and gripper limits are rejected before simulation advances. The environment receipt is queried before an uncertain action could be retried; acknowledged actions never execute twice. Interpolation and IK are generic execution services, not task controllers. The environment records both requested and applied actions.

The backend deterministically namespaces each model action ID by the actual episode ID before dispatch. Receipts and policy traces retain both `model_action_id` and `execution_action_id`. Reusing `a1` in a newly reset episode therefore creates a new valid action; retrying `a1` in the same episode returns its receipt without movement. Old-episode commands are rejected. This isolation also works when the launcher retains facade receipts across resets.

Defaults are 40mm maximum translation,0.15rad maximum rotation,20mm/s,0.15rad/s,0.05–3s duration and8N maximum force cap. Duration is quantized to60Hz and the actual duration is reported. Small moves near contact remain the policy's decision; these action bounds do not certify collision safety. Force caps are scoped to each action: move_ee and wait use the configured8N default; gripper supplies its explicit0–8N value for that action. A lower gripper-tool cap is not a persistent override for later moves. Caps are drive limits, not measured finger contact forces.

Receipts distinguish the model's `requested_duration_s`, the tick-aligned `quantized_requested_duration_s` and the measured `executed_duration_s`. An action interrupted by a physical termination may execute fewer ticks. Actual duration comes from recorded simulation-time endpoints, with executed-control-tick count as a fallback; missing measurements remain unavailable. Historical traces are preserved rather than rewritten.

## Budget and evidence

The shared ledger reserves cost before every network attempt, including retries. Timeouts and responses without usage retain their conservative reservation. Maximums are1500 attempts and$30 estimated total. Output limits, request/episode timeouts and bounded retries also apply. The ledger uses returned input/output/cache token usage when available and keeps requested/returned model, endpoint, retry index, status and wall time.

The public rates observed on2026‑10‑26 were$10 input,$50 output and$1 cached input per million tokens for prompts up to272000 tokens. The configured local context cap is80000 conservative estimation units: UTF8 text bytes plus8192 units per image and envelope overhead. This guard is not an actual tokenizer count. Account group multipliers are unknown: the ledger is a cost estimate at published rates, not a claim about actual account deductions. Image reservation is intentionally conservative and is not a contact-precision measurement.

GPT receives a compact camera view containing K, CV extrinsic, camera pose/mount, frame dimensions/time and coordinate conventions. Complete public calibration remains available through the environment API and in recorded data. Per-image transmitted K and resize provenance remain explicit. Action rejections report actual vector norms, speed, duration and applicable limits so the policy can repair an invalid bounded command. A local context-limit rejection is an input-contract error before any HTTP request or simulation action.

`controller.json` freezes prompt, tool schema, configuration, action limits and provider implementation hashes. `policy_trace.jsonl` records actual tool calls and receipts, observation IDs, simulation/inference times and usage. `summary.json` separates backend failure from the independently scored task result and retains the exact backend error code plus episode-specific network/cost totals. Provider errors and timeouts finalize as `MODEL_SERVICE_ERROR`; malformed model protocols finalize as `INPUT_CONTRACT_ERROR`; unknown or partial physical execution finalizes as `PHYSICS_INVALID`. Such failures cannot become valid physical task-failure samples. A verdict already produced by the physical environment is preserved. Ordinary action-budget completion remains independently scored. Full formal evaluation must use one frozen controller hash across all episodes; debug attempts remain separate.

Before every API decision, `observations/decision_XXXXXX/` saves the exact two already-encoded JPEG byte strings, the exact public observation JSON supplied as text, and a small SHA manifest. No second image encoding occurs. Trace references are relative to `gpt_control`, and request labels bind `policy:episode:observation_step:decisionN`; retries retain the same label. Failed API calls therefore retain their actual input images and state too. Native dataset images and MP4 frames are separate representations and are not claimed to reproduce these exact provider JPEG bytes. Credentials, HTTP headers and hidden reasoning are excluded from these observation files.
